# PickVia v1.3 Release Design

## Goal

Publish the completed DuckDuckGo browser support as PickVia v1.3 through the
existing public GitHub Release and GitHub Pages workflows.

## Release scope

Version 1.3 contains the reviewed DuckDuckGo work already committed on
`duckduckgo-browser-support`:

- discover official DuckDuckGo builds and offer `DuckDuckGo` plus
  `DuckDuckGo Private` as ordinary browser-level targets;
- route private links through a separate, preference-seeded real DuckDuckGo
  Fire Window without Accessibility automation or an extension;
- bind URL delivery, reuse, recovery, quarantine, and cleanup to exact process
  identity;
- preserve ordinary routing on trusted but not-yet-allowlisted DuckDuckGo
  versions while failing private support closed;
- migrate the former generated label `DuckDuckGo Fire Window` to the standard
  `DuckDuckGo Private` label without overwriting genuine custom labels.

No unrelated feature, visual redesign, signing-system change, or new screenshot
is part of v1.3.

## Version and documentation changes

- Change `Support/Info.plist` from short version `1.2`, build `3` to short
  version `1.3`, build `4`.
- Update `.github/SECURITY.md` so `1.3.x` is the supported line and `1.2.x` is
  no longer the current security-update line.
- Update README download, installation, and Gatekeeper copy from v1.2 to v1.3.
- Update `site/index.html` download labels to v1.3 and mention DuckDuckGo among
  the supported browser families.
- Add a 20 August 2026 v1.3 entry at the top of `site/changelog.html`; move the
  current-release badge from v1.2 to v1.3.
- Keep existing canonical URLs and `site/sitemap.xml` public-page coverage.

The release copy will call the user-facing target `DuckDuckGo Private` and may
explain that it uses a real Fire Window internally. It will state that no
Accessibility permission or DuckDuckGo extension is required.

## Artifact and integrity model

The repository's established public distribution model remains unchanged:

1. Build `build/PickVia.app` with `scripts/build-app.sh`.
2. Verify the app with `scripts/smoke-test.sh`, `codesign --verify --deep
   --strict`, bundle identifier `dev.bozhenpeng.PickVia`, short version `1.3`,
   and build `4`.
3. Package `dist/PickVia-v1.3.dmg` with `scripts/package-dmg.sh` and verify it
   with `hdiutil verify`.
4. Produce `PickVia-v1.3.dmg.sha256` and verify it locally with
   `shasum -a 256 -c`.
5. Publish both files on a `PickVia v1.3` GitHub Release.

The app remains ad-hoc signed and not notarized. README and release notes will
retain the existing explicit Gatekeeper and checksum instructions; the release
must not imply Developer ID signing or notarization.

## Integration and publication sequence

1. Run the complete WindowServer-capable Swift suite with warnings as errors,
   strict Swift formatting, diff checks, production build, smoke test, DMG
   verification, and checksum verification.
2. Commit only the v1.3 version, security-policy, README, and website changes on
   the feature branch.
3. Fast-forward local `main` to the reviewed feature branch while preserving
   the user's unrelated untracked files.
4. Re-run the full tests and artifact checks on merged `main`.
5. Push `main` to `origin`.
6. Create tag/release `v1.3` targeting `main`, upload the DMG and checksum, and
   verify the public release metadata and asset downloads.
7. Let the existing `Deploy PickVia site to GitHub Pages` workflow publish the
   changed `site/` directory and wait for a successful deployment.

No force push, destructive history rewrite, or unrelated staging is allowed.
The release tag and public release are created once; an ambiguous failure is
inspected before any retry.

## Production verification

The release is complete only after all of the following are true:

- `origin/main`, the v1.3 tag, and the GitHub Release resolve to the intended
  release commit;
- the release exposes both `PickVia-v1.3.dmg` and
  `PickVia-v1.3.dmg.sha256`, and the published checksum validates the published
  DMG;
- the GitHub Pages workflow succeeds for the release commit;
- the homepage, changelog, privacy page, terms page, and sitemap return HTTP
  200;
- every HTML page has its expected self-referencing canonical URL and neither
  page headers nor markup introduce `noindex`;
- the live homepage and changelog show v1.3 and their download links resolve to
  the v1.3 GitHub Release;
- the sitemap continues listing absolute canonical URLs for every public page.

Google Search Console sitemap submission and homepage indexing request will be
attempted only if an already-authorized property/session is available. Search
indexing can take days or weeks and is not a deployment-success condition.

## Cleanup and handoff

After the merge, push, release, Pages deployment, and production checks all
succeed, remove the owned feature worktree and delete the merged local feature
branch. Preserve the main checkout's pre-existing untracked files throughout.
